# 单问题执行可视化

启动原 API 服务后访问 `/agents`。提交一个问题，页面只调用一次原有 `SearchReaderPipeline.answer`。

每个窗口对应这次问答实际发生的一次 RWKV 调用，例如规划、网页阅读、证据提取、审核、归并或最终回答。窗口数量随真实调用增长，当前并发和峰值并发来自实际执行事件；不预建虚构窗口，也不额外生成多个研究问题。

节点展示输入材料预览、任务、排队、执行、重试及返回内容。模型的中间输出不等于经过审核的最终答案；例如坏摘要被原链路拒绝后，页面会显示回退原文的处理记录。

问答模型、提示词、检索深度、材料预算、审核轮次和结果均沿用原流程。最终结果原样返回，不另设 demo 的答案发布规则。观察回调失败不会中断模型调用。

页面的“停止查看”仅断开事件视图，后台问答继续执行并写入原有运行记录。聊天请求的并发限制仍有效；节点数量取决于实际工作量，不能把调用总数等同于同时并发数。

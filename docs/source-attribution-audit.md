## 实施顺序

1. 补验收：保留原题，为产品、版本、表格、来源要求添加对象—字段—值—原文位置的标准；增加值互换、引用互换、第三方自称官方的反例。关键词仅保留为基础格式检查，真实正文需逐项语义核对，并对评审器用这些反例校准。
2. 修候选选择：把对象、版本、指定文档地址作为独立约束，避免仅靠名称连续匹配排除真正原文；用户指定的原文必须进入阅读候选。
3. 保留证据身份：提取、汇总、字段裁决都传递实际 URL、标题、原文片段、对象和版本。网页自称“官方”不能直接视为身份已验证；未知则保留未知，不能依赖不断追加域名黑名单。
4. 修“已验证”语义：字段值有文字出处不等于官方身份及对象归属已确认。裁决与原文核对分开记录；冲突或审查失败不能升级为已验证，更不能静默覆盖正确分支。
5. 流式前检查：先完成证据和归属核对，再流式输出正文，前期继续发进度事件。评估遗漏、错误归属及延迟，不能只看 done。
6. 先用固定抓取材料回放，隔离搜索波动；再跑原有真实检索题，最后用未参与修改的新领域题验收。保留原始基线，分别报告检索、证据与最终回答指标。

只有证据已正确送入、模型仍持续串源时，才把对应能力单独构造成训练样例评估 StateTune。不要把全部测试原题混入训练，也不要用联网判断 state 承担回答事实核对。
